Продукт:      Тренажёр слепой печати для студентов, которые учат свои конспекты, перепечатывая их вслепую.
MVP входит:   Вставка своего текста (до 3000 символов), загрузка .txt, выбор из 5 готовых конспектов, загрузка случайного конспекта из Википедии по API, автозамена редких символов, посимвольный набор с подсветкой, подсказка клавиши и пальца, блокировка при опечатке до нажатия Backspace, расчёт скорости, точности и проблемных клавиш, сохранение и очистка истории тренировок, демо-данные, журнал событий и ошибок.
Не входит:    Регистрация и профиль, сервер, соревновательный режим, озвучка клавиш, загрузка .docx/.pdf, графики за год, тёмная тема.
Ограничения:  Один HTML-файл (плюс tests.html для автотестов), телефон 360 px, без внешних библиотек, без ключей API; весь интерфейс по-русски.
Как работать: Отдельный commit на задачу · структуру и названия не менять · состояния (пусто, загрузка, ошибка, много данных) обязательны · ошибки показывать словами · сначала план по шагам и ждать «да» · не больше двух файлов за шаг · без новых библиотек без спроса · рефакторинг делать отдельным коммитом без изменения поведения · любая библиотека только после проверки по 5 вопросам · технический долг записывать в ДОЛГ.md.
Безопасность: Ключи — только через переменные окружения, файл .env не коммитить (.gitignore) · настоящие данные пользователей ИИ не показывать (только выдуманные) · любой текст от пользователя проверять по длине (до 3000 символов) и выводить только как текст через textContent, а не как HTML.
Публикация:   Главный файл index.html всегда лежит в корне репозитория · при появлении сервера ключи вводить только руками в настройках хостинга · инструкцию ЗАПУСК.md обновлять при каждой новой зависимости.
Эксплуатация: В журнал событий не писать тексты конспектов и данные пользователей (только длину текста) · каждая ошибка в журнале записывается с причиной и с тем, что показали пользователю · обновление зависимостей делать по одной за раз.
Проверка:     Перед каждым commit открой tests.html, ПРОВЕРКА.md и УГРОЗЫ.md и покажи результат · на каждый критерий приёмки должен быть тест · если тест красный — не коммить и чини код продукта, а не тест · commit разрешён только при всех зелёных тестах.
Заморозка:    Заморозка изменений до защиты проекта — никаких новых функций, рефакторинга и «улучшений дизайна»; разрешены только критичные исправления из списка «сразу» в ПОКАЗ.md.
